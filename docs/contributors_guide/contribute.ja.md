# RIMAPIへの貢献

RIMAPIへの貢献に興味を持っていただき、ありがとうございます！このガイドでは、プロジェクトにコード、ドキュメント、またはアイデアを提供するために必要な情報をまとめています。あなたの貢献は、RimWorldコミュニティ向けのRIMAPIをより強力なツールにします。

## 貢献の方法

- **コード**: 新機能の実装、バグ修正、パフォーマンス改善。
- **ドキュメント**: ガイドの充実、サンプル追加、誤字修正。説明が一つ増えるだけでも助かります。
- **テスト**: 新機能をゲーム内でテストしてバグを見つけてください。
- **機能提案**: イシューを立てて新機能や改善案を提案してください。
- **コミュニティサポート**: GitHub DiscussionsやDiscordで他のユーザーを支援してください。

## はじめに: 最初の貢献

### 前提条件

- RimWorldのライセンス版（1.5以降）。
- .NET開発用のIDE:
    - **Visual Studio**: `.NET desktop development` ワークロードをインストールしてください。
    - **VSCode**: `C# Dev Kit` 拡張機能（`ms-dotnettools.csdevkit`）をインストールしてください。
- **.NET Framework 4.8** 開発者パック（またはプロジェクトがターゲットとするバージョン）。
- バージョン管理のための **Git**。

### 開発セットアップ

1.  **Fork と Clone**:
    -   GitHubでリポジトリを**Fork**して自分のコピーを作成してください。
    -   自分のフォークをローカルに**Clone**します:
        ```bash
        git clone https://github.com/Your-Username/RIMAPI.git
        cd RIMAPI
        ```

2.  **RimWorld のパスを設定**:
    -   プロジェクトは RimWorld のアセンブリを参照するためにインストール先を知る必要があります。
    -   `Source/Directory.Build.props` ファイルを見つけてください。
    -   `<RimWorldPath>` プロパティをあなたの RimWorld インストールディレクトリに更新してください。

3.  **プロジェクトをビルド**:
    -   IDEで `Source/RimApi.sln` ソリューションを開いてください。
    -   ソリューションをビルドして、依存関係が解決されプロジェクトが正しくコンパイルされることを確認してください。

4.  **機能ブランチを作成**:
    -   変更には新しいブランチを作成してください。`main`ブランチをきれいに保てます。
        ```bash
        git checkout -b feature/your-awesome-feature
        ```

## 新しいエンドポイントの作成

新しいエンドポイントを追加することは、貢献を始める良い方法です。ステップバイステップの詳細ガイドがあります。

- **[Creating Endpoints](./creating_endpoints.md) ガイドを読んでください。** DTO作成からコントローラーの実装まで、アーキテクチャと手順が説明されています。

## 開発ワークフロー

### コーディングとアーキテクチャの基準

-   **既存のパターンに従う**: 既存のコードベースとの一貫性を心がけてください。
-   **コントローラーは薄く**: コントローラーはリクエストの解析とレスポンス返却のみを行い、ビジネスロジックは**サービス層**に置いてください。
-   **サービスは調整、ヘルパーは実行**: サービスはワークフローをオーケストレーションし、**ヘルパー**には再利用可能な処理を置きます。
-   **DTOを使用する**: RimWorldの内部型をAPIレスポンスで直接公開しないでください。すべてのデータは`Models`ディレクトリ内のData Transfer Object（DTO）にマッピングしてください。

### 変更のテスト

プルリクエストを提出する前に、十分にテストしてください:

1.  モッドがRimWorldでエラーなく読み込まれること。
2.  APIサーバーが正しく起動すること。
3.  新しいエンドポイントが正しいデータとステータスコードを返すこと。
4.  いくつかの既存エンドポイントを簡単に確認して、回帰を起こしていないことを確認すること。
5.  エラーハンドリングが期待通りに動作すること（例: 無効なIDを渡した場合）。

### ドキュメントの更新

正確なドキュメントはコードと同じくらい重要です。

-   エンドポイントを追加または変更した場合、`docs/_endpoints_examples/examples.yml` のドキュメントを**必ず**更新してください。
-   大きな新機能を追加した場合、`docs/` ディレクトリに対応するガイドを作成または更新してください。

## プルリクエストの提出

-  **フォークへプッシュ**:
    ```bash
    git push origin feature/your-awesome-feature
    ```

-  **プルリクエストを作成**:
    -   元の RIMAPI リポジトリに移動します。
    -   「New Pull Request」をクリックして自分の機能ブランチを選択します。
    -   プルリクエストのテンプレートに、PRの目的とテスト方法を記載してください。

## ヘルプを得るには

-   **GitHub Issues**: バグ報告や特定の機能要求。
-   **Discord**: 公式の [RimWorld Modding Discord](https://discord.gg/Css9b9BgnM) に参加し、`#rimapi` チャンネルでリアルタイムの支援を受けてください。
